## 1. 总体架构

### 1.1 架构风格

采用**分层 + 事件驱动**架构：UI 层与业务层解耦，核心引擎以"录制会话（Session）"为中心，各 AI 能力作为独立服务模块，通过内部**时间轴事件总线**汇聚到统一的时间轴数据模型上。

```
┌────────────────────────────────────────────────────────────┐
│                     UI 层（PySide6）                        │
│   主窗口 / 录制控制面板 / 实时字幕区 / 会话管理 / 设置页      │
└───────────────────────────┬────────────────────────────────┘
                            │ Qt Signal/Slot
┌───────────────────────────▼────────────────────────────────┐
│                      应用层（app）                           │
│              会话状态机 / 全局配置 / 任务调度                 │
└──────┬────────────────┬───────────────┬────────────────────┘
       │                │               │
┌──────▼──────┐  ┌──────▼──────┐  ┌─────▼─────────┐
│  音频引擎     │  │ 视觉引擎     │  │  ASR 引擎      │
│  (core/      │  │ (core/      │  │ (ai/          │
│   audio)     │  │  vision)    │  │  asr)         │
│ WASAPI环回   │  │ 抓屏+翻页检测│  │ 本地whisper/  │
│ 16k PCM 流   │  │ pHash+SSIM  │  │ 云端流式API   │
└──────┬──────┘  └──────┬──────┘  └─────┬─────────┘
       │                │               │
┌──────▼────────────────▼───────────────▼────────────────────┐
│                时间轴事件总线（Timeline Bus）                │
│     TranscriptEvent(时间戳, 文本) / SlideEvent(时间戳, 截图)  │
└───────────────────────────┬────────────────────────────────┘
                            │
┌───────────────────────────▼────────────────────────────────┐
│                时间轴数据模型（Session Store）               │
│        内存事件流 + JSON 增量落盘（崩溃恢复）                │
└───────────────────────────┬────────────────────────────────┘
                            │
┌───────────────────────────▼────────────────────────────────┐
│                     导出层（export）                         │
│  MD 逐字稿合成 / Word 逐字稿导出 / AI 教程文档生成(python-docx)│
└───────────────────────────┬────────────────────────────────┘
                ┌───────────▼────────────┐
                │      AI 梳理引擎 (ai/llm) │
                │  分段摘要 → 汇总编排 → 配图  │
                └─────────────────────────┘
```

### 1.2 线程模型

| 线程 | 职责 |
|------|------|
| 主线程 | Qt UI 事件循环 |
| 音频线程（LoopbackRecorder） | WASAPI 环回采集，环形缓冲区写入 |
| ASR 工作线程（LiveTranscriber） | 消费音频块 → VAD 分段转写 → 发射 `TranscriptEvent` |
| 视觉线程（SlideDetector） | 定时抓屏 → 相似度计算 → 翻页判定 → 截图落盘 → 发射 `SlideEvent` |
| 收尾线程（StopWorker） | 停止录制后执行 MD 合成、元数据写入（v1.1 起，避免阻塞 UI） |
| 模型下载线程（_DownloadWorker） | 首次启动模型下载 + 进度上报（走镜像/系统代理/断点续传） |
| 导出/LLM 线程 | Word 导出、AI 教程生成（异步 + 进度上报） |

线程间通信用 Qt 信号（跨线程自动排队），音频数据用带锁环形缓冲区。

**录制状态机**（v1.1 起 UI 与状态机强联动，状态变化统一经事件总线 `state_changed` 信号广播）：

```
idle ──开始──> recording ──暂停──> paused
                  ▲                  │
                  └──────恢复────────┘
                  │
                  └──停止──> finalizing ──(收尾线程完成)──> idle
```

## 2. 技术选型

| 领域 | 选型 | 理由 |
|------|------|------|
| 语言/运行时 | Python 3.11+ | AI 生态最完整；faster-whisper/opencv/docx 均有成熟绑定 |
| 桌面 UI | PySide6 | Qt 官方 Python 绑定，LGPL 可商用，跨线程信号槽成熟 |
| 系统声音采集 | PyAudioWPatch | 支持 WASAPI Loopback，捕获系统播放声音 |
| 截图 | mss | 极快的全屏/区域/显示器截图（C 实现） |
| 翻页检测 | imagehash(pHash) + OpenCV(SSIM/直方图) 双重校验 | pHash 快速粗筛，SSIM 精确复核，抗噪性好 |
| 本地 ASR | faster-whisper（CTranslate2） | CPU/GPU 均可，中文 medium 模型准确率高，流式分段转写 |
| 云端 ASR（可选） | OpenAI 兼容接口 / 讯飞等 | 可配置替换 |
| LLM 梳理 | OpenAI 兼容 Chat Completions（DeepSeek/通义/GPT 均可） | 统一协议，供应商可配置 |
| Word 生成 | python-docx | 标题/段落/图片/样式控制完整 |
| 简繁转换 | zhconv | 纯 Python 词库转换，Whisper 中文输出统一为大陆简体 |
| 打包 | PyInstaller（onedir） | ASR 模型外置下载，避免 EXE 过大 |
| 日志 | loguru | 简洁、可滚动、便于排查现场问题 |

### 2.1 关键技术点

**（1）系统声音环回采集**：枚举 WASAPI Loopback 设备（默认输出声道），以 16kHz/mono/int16 重采样后写入环形缓冲；ASR 线程按 1~2 秒块消费；暂停录制时静默丢弃。

**（2）准实时转写策略**：本地 faster-whisper 采用"静音切分分段"：检测到语音结束（静音 ≥ 0.8s）即提交该段转写，段级时间戳取段起点；连续说话超过 15 秒（`max_segment_sec`）强制切一段，保证字幕最长 15 秒必更新。中文标点由模型自带恢复；**转写结果统一经 zhconv 转为大陆简体**（Whisper 中文常输出繁体）。云端模式为分段 HTTP 上传（OpenAI 兼容 `/audio/transcriptions`）。

**（2b）设备自动选择与 CUDA 探测（v1.1 新增）**：`device=auto` 时不再仅凭显卡数量选 CUDA——检测到显卡后先做一次**微型转写探测**，若 CUDA 运行库（cublas/cudnn 等 DLL）缺失则自动回落 CPU int8 并记录日志。此机制修复了"有 N 卡但无 CUDA 运行库的机器转写全部失败"的问题。

**（3）翻页检测算法**：

```
每 T 秒（默认 1.5s）抓取低分辨率参考帧
  → 与当前 PPT 基准帧比较：
     dHash 汉明距离 / pHash 距离 > 阈值A（粗筛）
     且 SSIM < 阈值B（复核）
     且 变化区域集中在"内容区"（可选 ROI，排除播放器控制栏）
  → 判定翻页：立即以原始分辨率截图保存
  → 连续 N 秒内若画面回退为历史某帧（哈希匹配），判定"翻回"，复用旧截图
防抖：触发后 3 秒冷却期，忽略视频动画过渡帧
```

**（4）长文本 LLM 分治生成**：

```
逐字稿按 PPT 页边界切成 ~3k 字的段
  → 每段调用 LLM：生成结构化要点（Map 阶段，并行）
  → 汇总所有段要点 + 全文目录 → LLM 生成最终教程文档（Reduce 阶段）
  → 指令要求 LLM 在需要插图处输出占位标记 {{slide:N}}
  → 导出时替换为真实图片
```

**（5）段落式逐字稿合成（v1.1 新增）**：`src/export/paragraph.py` 在导出时把逐句转写事件流合并为段落——遍历时间轴，遇 SlideEvent、说话间隔 > 6 秒或段落超 400 字即切段；中文片段直接拼接（转写片段本为连续语句）。MD 与 Word 导出共用该遍历器，保证两端结构一致。实时字幕面板仍逐句显示（便于盯屏），仅最终文档段落化。

**（6）模型下载可靠性（v1.1 新增，国内网络实测）**：`src/ai/asr/model_manager.py` 统一处理——
- 启动时设置 `HF_ENDPOINT`（默认 `hf-mirror.com` 镜像）+ 禁用 Xet 新通道（走经典 HTTP 以兼容进度回调）；
- **自动继承 Windows 系统代理**（读注册表注入 `HTTPS_PROXY`，Python requests 默认不走系统代理，直连 HuggingFace 会频繁中断）；
- `huggingface_hub.snapshot_download` 原生支持断点续传（`.incomplete` 残片续传）；
- `is_downloaded()` 校验 `model.bin` 权重文件而非仅 `config.json`（曾因此出现"判定已下载但加载失败"）；
- 自定义 tqdm 适配器把 HF 内部进度回调转成 UI 信号（补全 `refresh/format_dict/display` 等方法以兼容新版 huggingface_hub）。

### 3.1 核心接口定义（摘要）

```python
class ASREngine(Protocol):
    def start(self, on_transcript: Callable[[TranscriptEvent], None]) -> None: ...
    def feed_audio(self, pcm: bytes) -> None: ...   # 16k mono int16
    def stop(self) -> None: ...

class SlideDetector:
    def feed_frame(self, frame: np.ndarray, ts: float) -> SlideEvent | None
    # SlideEvent(ts, image_path, slide_index, is_backtrack)

@dataclass
class TranscriptEvent:
    ts: float          # 秒
    text: str
    confidence: float

class Timeline:
    def add(self, event: TimelineEvent) -> None      # 排序插入 + 落盘
    def merge_to_markdown(self) -> str               # 文本+截图按时间合并
```

## 5. 关键流程

### 5.1 录制主流程

```
用户点击"开始"
→ 模型完整性检查（缺 model.bin 则弹下载进度对话框，就绪前禁止录制）
→ 启动音频线程 / 视觉线程 / ASR 线程，状态机 → recording（按钮联动刷新）
→ 事件源源不断写入 Timeline（内存 + events.jsonl 落盘）
→ UI 实时刷新字幕（逐句）与截图缩略图
→ 暂停/恢复：状态机 ⇄ paused，UI 按钮即时切换，计时暂停
→ 用户点击"停止" → 状态机 → finalizing（UI 即刻反馈"正在停止并生成逐字稿…"）
→ 收尾线程：各线程优雅退出 → 段落式合成 transcript.md → 写会话元数据
→ 状态机 → idle → 提示：导出 Word / 生成 AI 教程
```

### 5.2 异常与恢复

- 崩溃重启后扫描未关闭会话目录：`events.jsonl` 完整即可重建时间轴并补齐逐字稿 MD；
- 云端 LLM 调用失败：指数退避重试，仍失败则标记待重试，不影响 MD/Word 逐字稿产出；
- ASR 队列积压：动态增大块长度，优先保证不丢音频（音频始终先完整落盘）；
- CUDA 运行库缺失：加载时微型转写探测，失败自动回落 CPU（v1.1 实测案例：有 N 卡但未装 cuBLAS，原实现每段转写均抛异常）；
- 模型下载中断：断点续传 + 镜像 + 系统代理（v1.1 实测案例：直连 HuggingFace 连续 3 次中断留下 `.incomplete` 残片）。

### 5.3 打包与发布

- PyInstaller onedir 模式（`build.spec`）：EXE + `_internal/`（约 344MB），免 Python 环境；
- 数据文件必须显式收集（`collect_data_files`）：**PyAudioWPatch 资源、faster-whisper 的 silero VAD onnx、zhconv 简繁字典（zhcdict.json）、loguru**——前两者缺失会导致转写全部失败，属隐蔽故障（代码能导入、运行时才炸）；
- 发布流程：清空测试产物 → **替换含真实 API Key 的 settings.json 为模板** → 压缩 zip → Git tag → GitHub Release 上传附件；
- 版本发布记录：v1.0.0-alpha（2026-09-27）、v1.0.1-alpha（2026-09-28）、v1.1.0-beta（2026-10-02，小范围公测）。

## 7. 风险与对策

| 风险 | 对策 | 实测情况 |
