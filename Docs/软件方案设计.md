## 1. 总体架构

### 1.1 架构风格

采用**分层 + 事件驱动**架构：UI 层与业务层解耦，核心引擎以"录制会话（Session）"为中心，各 AI 能力作为独立服务模块，通过内部**时间轴事件总线**汇聚到统一的时间轴数据模型上。

```
┌────────────────────────────────────────────────────────────┐
│                     UI 层（PySide6）                        │
│   主窗口 / 录制控制面板 / 实时字幕区 / 会话管理 / 设置页      │
│   全局热键（F9/F10/F11，录制时窗口失焦仍可操作）             │
└───────────────────────────┬────────────────────────────────┘
                            │ Qt Signal（全部 QueuedConnection）
┌───────────────────────────▼────────────────────────────────┐
│                      应用层（app）                           │
│         会话状态机 / 全局配置 / 任务调度 / 异步 Worker 框架   │
└──────┬────────────────┬───────────────┬────────────────────┘
       │                │               │
┌──────▼──────┐  ┌──────▼──────┐  ┌─────▼─────────┐
│  音频引擎     │  │ 视觉引擎     │  │  ASR 引擎      │
│  (core/      │  │ (core/      │  │ (ai/          │
│   audio)     │  │  vision)    │  │  asr)         │
│ WASAPI环回   │  │ 抓屏+翻页检测│  │ 实时档 small  │
│ 16k PCM 流   │  │ 三层判据     │  │ 离线档 large-v3│
└──────┬──────┘  └──────┬──────┘  └─────┬─────────┘
       │                │               │
┌──────▼────────────────▼───────────────▼────────────────────┐
│                时间轴事件总线（Timeline Bus）                │
│     TranscriptEvent(时间戳, 文本) / SlideEvent(时间戳, 截图)  │
└───────────────────────────┬────────────────────────────────┘
                            │
┌───────────────────────────▼────────────────────────────────┐
│                时间轴数据模型（Session Store）               │
│     内存事件流 + JSONL 增量落盘 + flush（崩溃可恢复）          │
└───────────────────────────┬────────────────────────────────┘
                            │
┌───────────────────────────▼────────────────────────────────┐
│                     导出层（export）                         │
│  MD 逐字稿合成 / Word 逐字稿导出 / AI 教程文档生成(python-docx)│
└───────────────────────────┬────────────────────────────────┘
                ┌───────────▼────────────┐
                │      AI 梳理引擎 (ai/llm) │
                │  分段摘要 → 汇总编排 → 配图  │
                └─────────────────────────┘
```

### 1.2 线程模型

| 线程 | 职责 | 约束 |
|------|------|------|
| 主线程 | Qt UI 事件循环；**所有 UI 操作只允许在此线程** | 铁律 |
| 音频线程（LoopbackRecorder） | WASAPI 环回采集，环形缓冲区写入 + 落盘 wav | — |
| ASR 工作线程（LiveTranscriber） | 消费音频块 → VAD 分段转写 → 发信号 | 只发信号 |
| 视觉线程（SlideDetector） | 定时抓屏 → 三层判据 → 截图落盘 | 独占 mss 实例 |
| 收尾线程（StopWorker） | 停线程 → join → 合成 MD → 写元数据 | `finally` 保证回 idle |
| 录音守护线程（RecorderWatch） | join 录音线程，异常时触发停止 | **绑定实例 + 会话代号校验** |
| 异步 Worker（QThread + _AsyncWorker） | 模型下载 / Word 导出 / AI 教程 / 离线重转写 | 只发信号，UI 回主线程 |

线程间通信**一律用 Qt 信号**；所有跨线程连接**显式指定 `Qt.QueuedConnection`**（见 §1.3）。
音频数据用带锁环形缓冲区（带丢块计数，见 §5.2）。

**录制状态机**（状态变化统一经事件总线 `state_changed` 广播，UI 按钮联动）：

```
idle ──开始──> recording ──暂停──> paused
                  ▲                  │
                  └──────恢复────────┘
                  │
                  └──停止──> finalizing ──(收尾线程完成)──> idle
```

`stop()` 幂等（`_stopping` 标志）；`_do_stop` 用 `finally` 保证**无论成败必回 idle**，
避免异常后卡在 finalizing 无法再次录制。

### 1.3 Qt 跨线程铁律（v1.2 强化）

这是本项目最容易被违反、且违反即随机崩溃的一条规则。v1.2 把它从"约定"变成"机制"：

| 规则 | v1.1 现状 | v1.2 做法 |
|------|-----------|----------|
| 后台线程不得操作任何 Qt 控件 | ❌ 违反：AI 教程生成线程直接调 `QMessageBox`/`QProgressDialog`（必崩路径） | 引入 `_AsyncWorker(QObject)`，后台只有 `Signal.emit` |
| 信号连接需保证槽在主线程执行 | ⚠️ 依赖 PySide 对普通函数的线程推断 | **全部显式传 `Qt.QueuedConnection`** |
| mss 实例非线程安全 | ❌ 违反：构造在主线程、grab 在检测线程 → 永久抛异常 | 实例绑定「首次使用者线程」，换线程则锁内重建 |
| 进度对话框不能长时间 `exec()` | ⚠️ 阻塞主事件循环 | 模型下载用 `exec()`（需防重复触发），其他用 `show()` |

> **实测教训（v1.2）**：`_AsyncWorker` 重命名信号（`finished`/`error` → `finished_ok`/`failed`）后，
> 测试 `test_download.py` 仍引用旧信号名而失败——信号契约必须有测试守护。

## 2. 技术选型

| 领域 | 选型 | 理由 |
|------|------|------|
| 语言/运行时 | Python 3.11+ | AI 生态最完整；faster-whisper/docx 均有成熟绑定 |
| 桌面 UI | PySide6 | Qt 官方 Python 绑定，LGPL 可商用，跨线程信号槽成熟 |
| 系统声音采集 | PyAudioWPatch | 支持 WASAPI Loopback，捕获系统播放声音 |
| 截图 | mss | 极快的全屏/区域/显示器截图（C 实现）；实例需线程隔离 |
| 翻页检测 | **纯 numpy 自研三判据**（pHash + diff_ratio + SSIM） | 见 §2.1(3)：imagehash/OpenCV 方案在本项目实测下判据方向错误 |
| 本地 ASR | faster-whisper（CTranslate2） | CPU/GPU 均可；**离线加载本地快照**（见 §2.2） |
| 云端 ASR（可选） | OpenAI 兼容接口 | 可配置替换 |
| LLM 梳理 | OpenAI 兼容 Chat Completions | 统一协议，供应商可配置 |
| Word 生成 | python-docx | 标题/段落/图片/样式控制完整 |
| 简繁转换 | zhconv | 纯 Python 词库转换，Whisper 中文输出统一为大陆简体 |
| 密钥存储 | **Windows DPAPI**（`CryptProtectData`） | 系统级加密，密钥由用户账户保管，零第三方依赖 |
| 全局热键 | **Win32 `RegisterHotKey`** + `QAbstractNativeEventFilter` | 系统级热键，不依赖 keyboard/pynput 等额外库 |
| 打包 | PyInstaller（onedir） | ASR 模型外置下载，避免 EXE 过大 |
| 日志 | loguru | 简洁、可滚动、便于排查现场问题 |

### 2.1 关键技术点

**（1）系统声音环回采集**：枚举 WASAPI Loopback 设备（默认输出声道），以 16kHz/mono/int16 重采样后写入环形缓冲；ASR 线程按块消费；暂停录制时静默丢弃。

**（2）准实时转写策略（v1.2 重写）**：见 §2.2 双档转写。
实时档采用"静音累积切分"——**注意 v1.1 的实现是错的**：原代码写
`self._tail_silence = self.silence_sec`（直接赋值而非累积），
导致任意 64ms 的瞬时静音都会立即出段，20 秒连续语音被切成数百段碎片。
v1.2 改为累积判定 + pre-roll 防切首字 + 尾部静音裁剪 + 背压自适应，回归测试证明 20s 语音 → 2 段。

**（2b）设备自动选择与 CUDA 探测**：`device=auto` 时先做**微型转写探测**，CUDA 运行库（cublas/cudnn）缺失则自动回落 CPU int8。修复了"有 N 卡但无 CUDA 运行库的机器转写全部失败"。

**（2c）模型离线加载（v1.2 新增）**：`LocalWhisperEngine` 原先直接 `WhisperModel(model_size)`，
faster-whisper 会**联网确认版本**，导致"模型明明已完整缓存在本地，却因代理 502 而加载失败"。
现改为：先把模型名解析为本地 HF 快照目录（`ModelManager.local_path()`），
再以 `local_files_only=True` 加载，全程零网络；本地确实没有才允许联网。
实测：修复前 `ProxyError: 502` 无法使用，修复后 1.2s 完成加载。

**（3）翻页检测算法（v1.2 重写，实测驱动）**：

原设计：`dHash 距离 > 阈值A **或** pHash > 阈值A` 粗筛 → SSIM 复核。
实测（400×600 白底 PPT，叠加 σ=3 高斯噪声）推翻了这一设计：

| 场景 | dHash 距离 | pHash 距离 | diff_ratio | SSIM |
|------|-----------|-----------|-------------|------|
| 同页 + 噪声 | **0.406** | 0.062 | 0.0000 | 0.905 |
| 仅光标移动 | — | 0.125 | 0.0017 | 0.997 |
| 真实换页 | **0.062** | 0.469 | 0.2773 | 0.675 |

> **关键结论**：dHash 对"整页亮度平移/噪声"的敏感度（0.406）**高于**对真实换页的敏感度（0.062），
> **方向恰好是反的**。原代码用 `or` 连接，等于把最不可靠的判据当成主判据，必然大量误检。
> 此外，设计文档声称的"SSIM 复核"**在 v1.1 代码中根本不存在**——文档与实现不符。

v1.2 改为**三层「与」结构**：

```
每 1.5s 抓取 256px 宽参考帧（区域均值降采样，非最近邻）
  → 第一层 pHash 主判据：距离 < 0.15 且 dHash < 0.225 → 判"未变"，返回
  → 第二层 diff_ratio 确认：差异像素占比 < 0.02 → 判"光标/水印/噪声"，更新基准后返回
  → 第三层 SSIM 复核：SSIM > 0.95 → 判"结构未变"，更新基准后返回
  → 三层均通过 → 判定翻页：以原始分辨率截图落盘
  → 若新帧与历史某帧 pHash 距离 ≤ 0.08 → 判"翻回"，复用旧截图（不重复存图）
防抖：触发后 3 秒冷却期
辅助：可选 ROI（归一化）排除播放器控制栏/弹幕区
```

标定阈值固化为 `tests/test_vision_algo.py` 的断言，改坏判据会立即测试失败。

**（3b）视觉线程的三个隐性故障（v1.2 修复，均导致翻页截图 100% 失效）**：

| 故障 | 现象 | 根因 | 修法 |
|------|------|------|------|
| mss 线程归属错配 | 每 tick 抛 `RuntimeError`，日志刷屏 | 实例 owner 绑在**构造线程**（主线程），grab 在检测线程 | owner 绑「首次使用者线程」，换线程则锁内重建 |
| 基准帧灰度为 None | 第二轮 `diff_ratio(None, gray)` 崩溃 | `_capture_now(sig=...)` 未传 `gray`，把 `_baseline_gray` 写成 None | gray 与 sig 互为推导，缺一自动补齐 |
| 截图目录不存在 | `FileNotFoundError` 被 `except` 吞掉，表现为"检测失灵" | 只假定 `create_session` 建好目录 | `SlideDetector.__init__` 内 `mkdir(parents=True, exist_ok=True)` |

**（3c）截图失败熔断**：截图失败按指数退避重试（0.2s→2.0s 封顶），
连续 5 次失败打一条 error 日志，连续 30 次（`_MAX_CONSECUTIVE_ERRORS`）退出线程并明确告知
"停止截图功能，录制与转写不受影响"——避免每 1.5s 刷一条 traceback 冲垮日志、掩盖真因。

**（4）长文本 LLM 分治生成**：

```
逐字稿按 PPT 页边界切成 ~3k 字的段
  → 每段调用 LLM：生成结构化要点（Map 阶段）
  → 汇总所有段要点 + 全文目录 → LLM 生成最终教程文档（Reduce 阶段）
  → 指令要求 LLM 在需要插图处输出占位标记 {{slide:N}}
  → 导出时替换为真实图片
```

**（5）段落式逐字稿合成**：`src/export/paragraph.py` 在导出时把逐句转写事件流合并为段落
——遇 SlideEvent、说话间隔 > 6 秒或段落超 400 字即切段。
MD 与 Word 导出共用该遍历器，保证两端结构一致。实时字幕面板仍逐句显示。

**（6）模型下载可靠性**：`src/ai/asr/model_manager.py` 统一处理——
- 启动时设置 `HF_ENDPOINT`（默认 `hf-mirror.com`）+ 禁用 Xet 新通道；
- **自动继承 Windows 系统代理**（读注册表注入 `HTTPS_PROXY`）；
- `snapshot_download` 原生支持断点续传；
- `is_downloaded()` 校验 `model.bin` 权重而非仅 `config.json`；
- 自定义 tqdm 适配器把 HF 内部进度转成 UI 信号。

### 2.2 双档转写策略（v1.2 核心架构变更）

**问题**：需求 NFR-01 要求"2 小时课程全程录制不丢帧、不死锁"，
NFR-02 要求"medium 模型中文字准确率 ≥90%"。这两条在纯实时架构下**不可同时满足**：

- faster-whisper medium int8 在 CPU 上实时率约 0.3~0.5x，
  2 小时课程要跑 4~6 小时，实时字幕根本跟不上；
- 实时模式为保实时性必须用 small/base，准确率达不到 90%。

**v1.2 方案**：按使用场景拆成两档，而不是在"快"与"准"之间二选一。

| 档位 | 模型 | 时机 | 目标 | 输出 |
|------|------|------|------|------|
| **实时档** | small（可配 base） | 录制过程中 | 不丢帧、字幕跟得上 | 边听边看的即时回顾 |
| **精度档** | large-v3（可配 medium） | **课后**离线 | 准确率优先，可用 GPU、beam_size=5 | 最终交付的逐字稿 |

`src/ai/asr/offline_retranscribe.py` 的工程要点：

- **静音分段**：按"噪声底(10百分位) + 30% 峰值区间"阈值切分，`max_sec=30`（Whisper 单窗上限内最优）；
  - 实测教训：单纯取能量百分位作阈值在稳态音源下会失效——分布过于集中时百分位落在语音能量本身，
    整段被判静音。修复后 6 段 / 覆盖率 94.2%（缺口恰为静音间隙，属正确行为）。
- **不覆盖原文件**：原 `events.jsonl` 备份为 `.bak`，失败可一键回滚；
- **保留截图事件**：只替换 transcript 事件，slide 事件原样保留（截图不重录）；
- **可中断**：长课程耗时数小时，支持进度回调与取消（在段边界检查取消标志）；
- **复用同一 ASR 引擎抽象**：本地/云端都支持，不为离线单独写一套。

菜单入口：【导出 → 离线重转写（提高准确率）…】，会在模型缺失时询问是否下载
（并提示 CPU 上 0.2~0.5x 实时速度的耗时预期），执行中可取消。

### 4.4 密钥加密（v1.2 新增，对应 NFR-06）

需求文档 NFR-06 要求"API Key 加密存储"，v1.1 自述为"未完成"。v1.2 用
**Windows DPAPI**（`CryptProtectData` / `CryptUnprotectData`）实现，零第三方依赖：

| 设计点 | 说明 |
|--------|------|
| 加密对象 | 当前 Windows **用户账户**——密钥由系统凭据保管 |
| 存储格式 | `enc:v1:<base64(CryptProtectData 输出)>`，与明文可区分 |
| 业务透明 | `AppConfig.get()`/`as_dict()` 返回**明文**；`save()` 落盘**密文** |
| 幂等 | 已加密的值不会被二次加密 |
| 向后兼容 | 旧版明文配置首次保存时**自动升级**为密文（懒迁移） |
| 失败处理 | 解密失败（换了账户/换了机器）返回空串并告警，**绝不返回密文当密钥用** |
| 非 Windows | 明确提示"密钥加密不可用"，功能降级为明文并告知用户 |

验证结论：磁盘无明文、重载得明文、旧版明文自动升级、密文不含原文。

### 4.5 运行时可观测性（v1.2 新增）

`session.json` 的 `stats` 字段记录本次会话的运行时指标，用于事后判断质量与性能：

```json
{
  "stats": {
    "asr":         {"asr_calls": 128, "asr_seconds": 412.7, "segments_out": 96,
                    "speech_sec": 7200.0, "realtime_factor": 0.057},
    "audio_queue": {"pushed": 72000, "dropped": 0, "capacity": 300},
    "vision":      {"ticks": 4800, "captures": 42, "backtracks": 3,
                    "rejected_noise": 17, "rejected_cursor": 8, "capture_errors": 0}
  }
}
```

> `dropped > 0` 说明 ASR 消费不及、音频队列曾丢块（音频已先完整落盘 wav，不影响最终重转写）。
> `capture_errors > 0` 说明截图曾失败（详见日志）。这些指标让"运行了 2 小时到底顺不顺畅"
> 变成可量化的答案，而不是靠感觉。

## 5. 关键流程

### 5.1 录制主流程

```
用户点击"开始"（或从课件播放器按下 F11）
→ 模型完整性检查（缺 model.bin 则弹下载进度对话框，就绪前禁止录制）
→ 启动音频线程 / 视觉线程 / ASR 线程，状态机 → recording（按钮联动刷新）
→ 事件源源不断写入 Timeline（内存 + events.jsonl 落盘）
→ UI 实时刷新字幕（逐句）与截图缩略图
→ 暂停/恢复：状态机 ⇄ paused，UI 按钮即时切换，计时暂停
→ 用户点击"停止"或按 F11 → 状态机 → finalizing（UI 即刻反馈"正在停止并生成逐字稿…"）
→ 收尾线程：各线程优雅退出 → 段落式合成 transcript.md → 写元数据（含 stats）
→ 状态机 → idle → 提示：导出 Word / 生成 AI 教程 / 离线重转写
```

**全局热键**（录制时主窗口通常失焦，必须系统级）：

| 键 | 动作 | 说明 |
|---|------|------|
| F9 | 手动截图 | 翻页漏检时的补救；线程安全投递，<100ms 响应 |
| F10 | 暂停 / 继续 | |
| F11 | 停止录制并生成逐字稿 | |
| Ctrl+Shift+F9 | 唤起主窗口 | |

> 被其他程序占用时 `RegisterHotKey` 返回失败，自动降级为仅界面按钮可用，
> 启动日志与窗口底部都会明确提示——**提示内容与实际注册结果严格一致**
> （`ControlPanel.apply_hotkey_hints()` 用注册结果回写按钮 tooltip）。

### 5.2 异常与恢复

| 场景 | 处理 |
|------|------|
| 启动录制失败（ASR 初始化异常等） | `abort_start()` 回滚：停半启动线程 + join + 删空会话目录，不留幽灵线程与空目录 |
| 崩溃重启 | 扫描未关闭会话目录，`events.jsonl` 完整即可重建时间轴并补齐 MD |
| 云端 LLM 调用失败 | 指数退避重试；仍失败则报错，**不影响 MD/Word 产出** |
| ASR 队列积压 | 背压自适应：pending 超阈值时动态增大 `max_segment_sec`（上限 3 倍），优先保证不丢音频 |
| 环形缓冲区满 | 实时性优先丢弃最旧块，**但计数并写入 `stats.audio_queue.dropped`**（v1.1 是静默丢弃，无任何记录） |
| CUDA 运行库缺失 | 微型转写探测失败 → 自动回落 CPU int8 |
| 模型下载中断 | 断点续传 + 镜像 + 系统代理继承 |
| 模型已缓存但联网失败 | v1.2：解析本地快照目录 + `local_files_only=True`，**全程零网络** |
| 截图持续失败 | 指数退避 + 熔断（连续 30 次退出线程），明确告知"录制与转写不受影响" |
| 退出时仍有后台任务 | 弹窗告知任务数与强制退出风险，由用户决定 |
| 退出时正在录制 | 三选一：停止并退出 / 仅退出 / 取消；"停止并退出"会等待收尾最多 15s |

### 5.3 打包与发布

- PyInstaller onedir 模式（`build.spec`）：EXE + `_internal/`，产物 344MB / 375 文件，压缩后 135MB；
- **数据文件必须显式收集**（`collect_data_files`）：**PyAudioWPatch 资源、faster-whisper 的 silero VAD onnx、zhconv 简繁字典（zhcdict.json）、loguru**——前两者缺失会导致转写全部失败，属隐蔽故障（代码能导入、运行时才炸）；
- **打包后自检（v1.2 新增，关键工程实践）**：`build_package.py` 在构建完成后自动运行
  `tests/test_packaged_smoke.py`，它以**独立工作目录**启动 EXE 并执行 `--selftest-to <json>`，
  断言 13 项关键能力全部可用（含 DPAPI、事件落盘、MD/Word 导出、视觉判据、UI 构建）。
  理由：源码测试全绿**不等于**打包产物可用——资源漏收、导入路径错误、frozen 环境差异
  只有真正跑 EXE 才能暴露。任一项不过则构建失败，产物不予交付。
- **自检模式安全约定**：进入自检时置 `LESSONRECORDER_SELFTEST=1`，
  `SessionManager.start()` 见到该变量直接拒绝启动——
  即使参数解析出意外，也绝不会在自动化探测时真的去录音和截屏。
  （实测教训：v1.2 首次打包自检时，`--selftest-to` 因严格相等判断落空进入 GUI 分支，
  真的录了一段音并污染了 dist 产物目录。）
- 发布产物：`release/AI-LessonRecorder-v1.2.0-win-x64.zip` + `.sha256` 校验文件。

### 8.1 缺陷模式总结（供后续参考）

这批缺陷集中在四类模式上，值得作为后续 code review 的检查清单：

1. **"赋值"与"累积"混淆**（#1）——状态量是累计值还是瞬时值，必须明确。
2. **文档声称 ≠ 代码实现**（#8、#16、#17）——设计文档要能被测试反证。
3. **线程归属假设错误**（#2、#3、#5）——"我在哪个线程建的"不等于"我在哪个线程用"。
4. **静默失败**（#6、#9、#14）——`except` 吞掉异常、计数器不记录，
   会把"功能失效"伪装成"功能正常"，是最难排查的一类。

> **工程原则**：不可观测的失败等于没有失败。
> 因此 v1.2 给每个关键子系统都补了指标（§4.5），并把它们写进产物可读的文件。
